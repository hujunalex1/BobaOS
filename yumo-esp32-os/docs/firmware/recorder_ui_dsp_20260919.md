# 录音机操作与双麦降噪

本页路径以工程根目录下的 `firmware/` 为起点。本文说明现有行为；构建、设备和服务状态以[项目当前状态](../current-state.md)为准。

## 界面与操作

适配240×240屏幕；沿用暗色、灰色按钮、红色录音主按钮。顶部原“录音机”标题改为状态/提醒，长提示可滚动，不再占用计时下方一整行。

- 计时使用18px字库，录音实心圆28px，其他控制图标24px。
- 录音主按钮118×77；首次点击开始，录音中点击暂停，再点击继续写入同一文件。
- 主按钮与右侧控制组上下边缘对齐；顶部停止键121×40，下面是播放控制。
- 快退、暂停/继续、快进的触控区分别为39×36、40×36、40×36；控制按钮仅显示图标。
- 时间后方条形区域与文字尾部相隔5像素，延伸到右侧留4像素。录音时显示输入电平，播放时改为播放进度；暂停保留位置，快退向前、快进按实际播放位置更新，不显示模拟声波。
- 列表从y=142开始，高98px；每行38px，删除按钮38×38，文件和删除区域分离；日期、时间分两行显示，保留文件名中的毫秒和序号以区分连续录音。

| 状态 | 可用控制 |
| --- | --- |
| 空闲 | 录音、刷新、返回、列表文件和删除 |
| 录音/录音暂停 | 大录音按钮暂停/继续、停止、返回 |
| 播放/播放暂停 | 快退、暂停/继续、快进、停止、返回、大录音按钮及当前播放文件的删除按钮 |
| 读取列表、打开音频、保存、删除中 | 相应冲突操作暂时禁用，等待任务结束 |

播放时，停止键结束播放；返回退出录音App；点击大录音键先停止播放器，待文件和音频设备关闭后开始新录音。列表切换文件、刷新及其他文件的删除仍禁用，避免并行占用SD或旧任务结果影响新任务。

## 有声快退与保调快进

- 按住快退：从当前位置以2倍速度倒放对应声音，进度向前移动。这是低内存的有声倒放，不保持语音音调或词序；到文件开头结束播放。
- 按住快进：以2倍速播放，音调设为原音调，不通过提高I2S采样率来加速；到文件末尾结束。
- 松开或滑出按钮后恢复此前的正常播放或暂停状态；原本暂停时也可以按住预听，松开继续保持暂停。
- 播放结束、错误、松手、弹窗、禁用和退出都会清除快进/快退的按压状态，不再一直高亮。
- PWR关屏暂停并清除快进/快退；亮屏后手动继续。退出协作停止任务，文件/codec关闭后释放资源。

普通播放和快退共享2KiB采样缓冲，快退逐块反转、低通并2:1抽取，不加载整段录音。快进复用项目已有的乐鑫 `esp_ae_sonic`，speed=2.0、pitch=1.0；额外1KiB输出缓冲及Sonic内部状态仅快进期间分配，离开快进、暂停、停止或退出即释放。1KiB不是Sonic全部内存开销。所有播放固定16kHz、16bit、单声道输出。

## 删除录音

点击文件行末尾垃圾桶，确认后才删除。播放期间只允许删除当前播放文件：弹窗打开时取消快进/快退；取消或返回仅关闭弹窗，不删除。确认后先停止播放，等待原任务完全关闭文件/codec，再向存储线程提交删除。

确认弹窗显示可滚动的完整文件名，**左侧确认删除、右侧取消**。旧布局的右侧确认键与列表第二行垃圾桶位置重叠，已通过真实LVGL指针回放复现同位置连点误确认；当前布局使再次点原位置落在取消区域。该复现不证明用户报告的所有历史文件消失均由此原因造成。

删除目标固定为所选文件路径、SD代次、文件大小和修改时间；执行前重新检查，变化则拒绝删除并要求刷新。存储worker取得修改权限后才删除，只接受 `/sdcard/recordings/` 下的单个普通 `.wav` 文件，不删目录、`.part`或其他类型，不格式化卡。大小/时间不是内容哈希，不能承诺识别所有外部同名替换。退出时撤销未提交的删除；已进入底层I/O的操作安全收尾，不强杀持锁任务。真实录音不能用作删除测试。

刷新失败会保留旧列表供查看，并禁止旧条目操作，避免错误地显示为全部文件消失。列表仍最多展示256项、检查4096个目录项，未展示不代表被删除。新录音探测目标路径时，只有明确不存在才创建；其他读取错误停止创建。封口改名失败保留`.part`并报告错误，已有目标不覆盖。没有自动备份、历史录音恢复或真实SD修复操作。

## 双麦与成熟降噪模块

使用从Xiph.Org官方仓库固定标签`SpeexDSP-1.2.1`取得的预处理/降噪源码，保留BSD许可。没有引入语音识别模型、回声消除器、编解码器或额外模型分区。来源哈希和裁剪范围见`components/recorder_dsp/PORT.md`。

链路为：双路MIC1/MIC2 → 分路去直流/检查削波 → 有条件混合或稳定择路 → SpeexDSP降噪 → 有界增益/限幅 → 单声道WAV。

- 只有两路正相关程度足够高、能量接近且都未削波时，才逐渐混合两路；反相、音量失衡或削波时回到原来的稳定择路策略。未测麦克风间距/方向，不冒充波束成形。
- SpeexDSP按16ms帧处理，降噪参数为-12dB，采取保守设置以减少过度处理；该数值是算法参数，不是实测所有噪声都降低12dB的承诺。
- 关闭SpeexDSP自身AGC和VAD截断，保留原有2倍基础、最高8倍的数字增益及±30000限幅；语音概率只限制额外增益，不删除音频帧，避免把稳定底噪一直放大。
- 对16ms首帧延迟进行补偿；暂停/停止时输出剩余尾帧，继续前重置处理状态，文件累计帧数与已处理的采集帧数一致，暂停时长不写入。
- 录音任务启动时按需分配64KiB PSRAM工作区，另有少量控制状态；处理期间无逐帧堆分配，退出/停止后释放。上游初始化的未检查分配通过受限内存池和C内错误边界保护，内存不足返回错误，不继续空指针录音。
- ES7210双路36dB与寄存器校验保持，16kHz/16bit/mono WAV及约1.92MB/分钟保持。旧录音不重写，播放不再经过录音降噪链路。

不是回声消除或实测音质保证；双麦空间关系、背景噪声、轻声表现、处理耗时和持续录音稳定性仍需设备验证。
