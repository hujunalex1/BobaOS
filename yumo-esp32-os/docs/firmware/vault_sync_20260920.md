# 密码本同步鉴权与全量覆盖（2026-10-31更新）

设备代码路径以工程根目录下的 `firmware/` 为起点。最新源码支持[HTTP/HTTPS域名同步](vault_public_https_20261031.md)；构建、设备和服务状态以[项目当前状态](../current-state.md)为准。本工程 `server/` 提供独立服务；其他私有部署的说明与代码不包含在本仓库。

## 密钥分工

| 内容 | 来源及用途 | 更新边界 |
| --- | --- | --- |
| 编译内置同步密钥 | 设备 `main/core/vault_deploy_key.hpp`，旧独立服务 `src/main/java/com/joyvault/BuiltinSyncKey.java`，现用服务中心维护对应密钥；只用于同步鉴权 | 修改两端源码后重新编译、部署及烧录，双方必须一致 |
| 既有存储密钥与身份 | 设备 `main/core/vault_builtin.hpp`，服务对应部署的 `config/local-keys.json`（旧独立服务使用 `deployment/local-keys.json`） | 保持原存储key、vault_id、salt及原Bearer令牌；不能随同步密钥更换而重新生成 |
| 设备图形密码 / 服务管理员 | 分别控制设备解锁与网页管理 | 两套密码独立；不作为同步密钥 |

更换**同步密钥**不改变设备已保存密码、管理凭据配置或服务端数据库的加密方式；更新后仍用原设备图形密码读取本地数据。这个保证不适用于自行更换**存储密钥/身份**。SD配置只保存地址，不提供或覆盖密钥。`tooling/firmware/configure_vault.py`只维护既有身份头，不生成同步密钥。

请求同时带原Bearer令牌及 `X-Vault-Key`，后者为双端编译密钥的固定域SHA-256证明；服务端强制验证，成功的bundle响应返回同一证明，设备在接收正文前检查其存在、唯一且匹配。旧服务不返回该响应头，不能与新设备配套；具体格式见[协议](../server/PROTOCOL.md)。外部JSON不能关闭或替代编译内置鉴权。

## 同步规则

- 每次点击“同步”都会下载服务端完整密码列表并覆盖设备端，不比较数据版本，不与旧条目合并。
- 服务端新增、修改、删除都反映到设备；有效空列表会清空设备列表。
- 下载、身份、格式或认证解密校验失败时，不用失败内容替换旧密码库。提交仍使用原双槽机制；极少数提交结果不明确时保持原重新读取处理。
- 本次HTTPS适配不改变已有设备图形密码或存储格式。JYVAULT2文件格式及兼容的本地加密配置继续使用；仅加密文件字节与地址均相同时避免重复擦写Flash，不影响同步成功和列表一致性。
- 先使用本地地址，失败后提示并读取SD配置，再重试一次；SD地址成功同步才持久保存。

完整流程：校验同步请求及响应 → 校验文件长度/格式/存储身份 → AES-GCM认证解密与条目校验 → 非当前槽写入及读回校验 → 最后提交槽头。只更换同步密钥不触发本地重加密；失败不将旧库当空库，不自动擦除或强制格式化。

## 失败提示与处理

| 提示 | 检查 |
| --- | --- |
| 设备同步身份不匹配（401） | 检查原Bearer令牌与配套存储身份是否混用了其他部署，不删除数据处理 |
| 同步密钥不匹配，请更新双端程序（403） | 核对烧录固件与运行JAR是否包含相同编译内置同步密钥 |
| 服务端密钥校验失败，请更新服务 | 可能仍连到旧服务或响应头缺失、重复、不匹配；核对地址和实际运行JAR |
| 密码文件格式错误或身份不符 | 核对文件及原存储身份，而不是重新生成同步密钥 |
| 密码文件校验失败，原数据未修改 | 检查文件认证解密路径，保留原库供排查；不等同于已证实文件损坏 |
| 连接失败或下载中断 | 检查Wi-Fi、地址、服务进程、防火墙和无线隔离 |

首个地址失败且SD配置不可读时，同时保留首次失败原因与SD错误，避免只显示“找不到SD配置”而掩盖鉴权问题。SD地址也失败则结束，不后台无限重试、不保存失败地址。

## 历史验证与当前使用边界

2026-09-23已完成匹配服务部署和设备烧录：服务鉴权及现有82条密码快照校验通过，原管理员未变；COM4四区烧录及启动检查通过，未写NVS/vault/SD。交付收据（历史回放记录）。**设备上点击同步的结果仍待用户测试**，不能把服务端校验或启动日志当成实机同步成功。

设备AES-GCM使用独立软件实现，不依赖硬件DMA/multipart路径，长数据每2048字节协作让出CPU，认证失败清除输出；SHA-256现使用独立软件实现（4KiB协作分段），管理密码的PBKDF2-HMAC-SHA256仍为10000轮；10月30日已优化为复用同次调用的HMAC状态，兼容既有验证结果并保留失败等待。908次生产C实现的隔离合成向量验证通过，不代表独立密码学审计或长期性能验证。

固定证明值不是随机挑战响应，不能防止凭据泄漏后的重放。HTTP仅用于可信局域网；公网使用通过证书及域名校验的HTTPS入口。TLS传输保护不替代既有同步身份与响应证明检查，不将内置密钥、证明值、令牌或真实密码写入文档/日志。2026-10-31生产地址与HTTPS回放已通过，这一功能已纳入11月2日成功烧录基线，实际公网同步仍待验收，见[公网HTTPS说明](vault_public_https_20261031.md)。

## 本地分区读取保护

同步鉴权与本地读取错误分别处理。当前分区读写用每次分配的1KiB内部缓冲，槽I/O失败、算法校验未完成和结构/摘要无效分别反馈；任一槽I/O/算法错误时终止，不选旧槽继续写入。结束清零释放，原存储身份、管理凭据和双槽格式不变。详见[密码分区提示](password_vault.md)。
