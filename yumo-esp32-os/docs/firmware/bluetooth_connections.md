# 蓝牙连接与设备切换

更新至2026-11-02已烧录固件。设备同时只连接一个蓝牙设备：可以作为HID键鼠向电脑/手机输入，也可以作为主机接收外接BLE键盘/手柄。蓝牙音乐发送媒体控制键，不传输A2DP音频。

## 使用方法

| 场景 | 操作与结果 |
| --- | --- |
| 开机/深睡重启 | 蓝牙默认开启，优先尝试最近目标对应的有效安全绑定；走与雨墨“连接”按钮相同的流程，不轮询尝试其他历史设备。 |
| 首次配对电脑/手机 | 点击“允许发现”，再到对方蓝牙设置中选择雨墨当前广播名称并完成配对；窗口最长60秒。 |
| 连接已保存电脑/手机 | 在已配对列表选择目标，再点连接；设备仅邀请该目标，必要时在对方蓝牙设置中点已有配对记录连接。 |
| 从电脑切换到手机，或反向切换 | 直接选择另一条有效的已配对记录并点击“切换至此设备”。系统先结束旧输入与旧链路，待收尾完成后再邀请所选设备。 |
| 已连接时允许发现 | 先断开当前连接，再开启60秒被动发现窗口；不会主动选其他设备。再次点击取消。 |
| 接入外接键盘 | 搜索附近可连接BLE键盘后选择；已配对键盘先确认附近存在，再连接并发现HID报告。 |
| 断开或取消 | 撤销本次操作，不自动连接其他设备，也不自动回到旧主机。之后需要再次手动选择或允许发现。 |
| 离开App | 本App尚未完成的请求撤销；已经建立的系统蓝牙连接保留，App实例/UI正常释放。 |

“搜索附近”用于外接BLE键盘/手柄。iPhone或电脑是向本设备发起连接的一方，不能用附近列表中搜不到它来判断是否可以配对。被动发现允许对方选择本设备，已保存目标邀请则限定一个身份；二者含义不同。

开机先在OUR_SEC有效安全绑定中匹配最近目标；无匹配时按同类安全记录顺序回退。元数据仅是偏好，不能替代真实绑定；不跨OUR_SEC/PEER_SEC比较计数，不因本端记录没有LTK而错误排除已配对目标。“自动连接”普通电脑/手机时本设备仍是Peripheral，只对选定主机开放有限邀请，最终由对方Central发起连接；因此不能保证所有手机/电脑在锁屏或蓝牙页面关闭时都响应。用户手动选择、取消、断开或关闭开关优先，取消后不再被本轮开机意图抢连。Wi-Fi同时默认开启并尝试最近成功网络。

设置、密码本连接页和FC蓝牙子页共用系统连接流程。FC子页返回FC游戏列表，已连接键盘可继续用于游戏。列表和详情以名称及下方小字地址辨认目标，等待期间显示选定目标，不用短连接临时身份反复替换。

安全绑定容量为16个，CCCD容量128条；名称/角色元数据16条，兼容读取旧8条v1数据。紧凑安全绑定后端为 `yumo_ble_store`，NVS分区大小保持；迁移失败保留原数据并报告错误。各模式按不同地址独立保存，不按相同名称合并；同时仍仅一条连接。满时明确失败，不自动淘汰其他绑定。普通四区烧录保留NVS，不能把“清除所有配对”当作日常升级步骤；确需删除时由用户选定并确认。

## 流程与状态

`SystemService`唯一worker持有`BluetoothConnectionFlow`，应用仅提交值请求；操作类型为Discover、Saved或Keyboard，并保存目标、切换阶段和错误。无线回调只更新底层状态，不操作App控件。

1. 已保存目标首先检查安全绑定仍有效；无效行不能拆掉正在工作的连接。
2. 撤销旧输入和邀请、请求断开，等待实际链路收尾；等待上限10秒。
3. 再次核对绑定，启动用户指定的邀请/键盘连接。连接阶段120秒为总兜底；主机邀请仍限60秒，键盘presence scan为10秒，输出安全等待30秒、外接安全等待90秒、加密后HID发现20秒。
4. 按真实加密和HID就绪状态确认Connected；每次快照按实际可用peer刷新所有已配对行，不能同时显示两台已连接。
5. 新的明确选择可替换等待中的目标；取消、关闭或深睡撤销未完成操作。旧代次回调不能启动新操作或取消新广播。

已保存主机使用普通可连接广告、controller allowlist和连接/加密时的身份及角色复核，支持SDK的IRK/RPA解析；完整设备名在扫描响应，HID服务/appearance在主广告。不能退回旧定向广播方案，也不能按名称匹配身份。最终是否发起连接由手机/电脑决定。

唯一的有限恢复发生在**尚未建立成功的Peripheral短连接**：远端以0x13收尾、无真正SMP错误且未本地取消时，可在原邀请窗口剩余时间恢复同一被动邀请。它不延长60秒、不切目标、不主动连接，也不适用于成功建立后断开的链路。

## 本次修复依据

之前采集到`ENC_CHANGE(status=0)`早于应用`CONNECT`，后者描述符已经bonded/encrypted。旧逻辑忽略提前加密完成，仍等待30秒，最终本地主动断开。SDK的连接通知顺序允许出现这种情况。

现在CONNECT、ENC_CHANGE和延迟检查统一经过`completeSecureConnection()`；同代次的GATT发现/持久化只做一次，但重复事件仍核对身份和实际安全策略。私密输入仍要求已加密、已绑定及128位密钥。

`rc=7`为`BLE_HS_ENOTCONN`，采集中发生于短连接的SMP收尾，不能直接当作真实配对/加密错误。控制器已接受连接但CONNECT尚未回调、断开清理未完成等空档纳入`connectionIdle()`；广告代次防止迟到的旧结束通知覆盖新邀请。界面使用稳定的用户操作状态，不跟随Advertising/Connecting瞬态来回切按钮。

Wi-Fi已有内存/连接修复保留：LVGL渲染和GUI工作栈优先PSRAM、XiP保护、内部DMA缓冲及事件阶段隔离不回退。本轮sdkconfig/defaults同步扩容安全绑定与CCCD，保留SM_LVL=2及禁用NimBLE隐藏连接重试。

- 烧录收据（历史开发记录未随源码分发）：四区hash、30秒实机启动及BLE初始化通过；NVS/vault前后哈希一致，未写SD。

10月1日最新烧录（历史开发记录未随源码分发）确认开机Wi-Fi取得IP、BLE安全连接事件成功；开机逻辑回归（历史开发记录未随源码分发）记录最近配对选择及连接流程检查。不同手机/电脑的自动响应、互切和取消/超时交互仍需实测；一次启动成功不等于全部主机兼容。

后续排查记录操作顺序、角色、阶段和错误码，区分“等待对方”“配对中”“已连接”；不要仅因rc=7或主机未立即响应就清库或清全部配对。最新固件信息见[当前状态](../current-state.md)。

## IINE-1001 / L1162模式分工

| 模式 | 当前用途 | 验证边界 |
| --- | --- | --- |
| C | FC方向、A/B、Start/Select | 用户已确认方向/A/B可用；仍非全部游戏验收 |
| H | 方向选择可控元素、A确认、B返回；时钟左右翻页 | 基于实采HID描述符和六个input报告引用识别，通用GAP名称也可恢复profile；最新返回/翻页修复已烧录，待复测 |
| 其他模式 | 可按独立地址保存连接记录 | 未重新实测协议，不承诺全部按键映射 |

切换模式后请将不同名称/地址视为不同设备进行连接。H模式返回通过系统输入路由交给当前页面，优先处理弹窗/面板与页面返回；C模式用于FC游戏。手柄HID就绪时FC隐藏并禁用触屏摇杆，断开恢复，连接变化清除旧按键。详见[FC操作](fc_touch_controls.md)。

## 11月1日至2日鼠标与存储修正

触控层提交完整位移，NimBLE任务按报告范围分包发送，资源不足按队列重试；释放、退出、断开和连接代次变化会撤销旧输入，避免旧动作发送到新连接。界面采样和发送频率解耦，不在GUI里等待多包发送。

鼠标卡顿追加排查发现notify的INFO日志可同步堵塞USB输出；现在压低该高频路径日志，保留会话摘要和必要错误。宿主可复现日志阻塞，但不是实测光标延迟；当次采集的5次断开为4次本地主动和1次远端用户终止，不能推断为无线监督超时。

构建时 `nimble_hid_input.cmake` 与 `nvs_blob_recovery.cmake` 校验固定SDK函数摘要后生成适配副本，未知SDK拒绝配置，不直接改磁盘SDK。16绑定、旧记录迁移、删除与NVS恢复已有合成存储/SDK回放；满容量长期使用、实际掉电与射频稳定性仍待实测。

以上修正已纳入11月2日成功烧录固件。回放和短时启动不代表蓝牙鼠标长期体验已获用户验收；最新证据见[当前状态](../current-state.md)。
