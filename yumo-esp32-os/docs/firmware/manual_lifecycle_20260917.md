# 按需应用与无线连接生命周期

本页路径以工程根目录下的 `firmware/` 为起点。本文说明现有行为；构建、设备和服务状态以[项目当前状态](../current-state.md)为准。

## 界面

蓝牙键鼠、蓝牙音乐移除顶部设备名称/地址区。设置的已配对、附近设备、设备详情以及系统配对弹窗仍显示名称和小字地址，避免连接对象不明。

键鼠顶部44px，保留65px键盘切换、44px倍率下拉和2px连接竖条。鼠标区从y45开始高195；键盘全宽240，快捷键79×48、字符键79×40。切换键盘时不显示右滚条；Win/Mac组合键提示、九宫格、鼠标功能不移除。音乐唱片区扩至138px，保留原六个媒体控制按钮，不虚构歌名/进度。

时钟表盘区240×240，取消底部三按钮、切换提示和选择器；仅通过左右滑动切换数字、指针、混合、黄历四种表盘。保留年份、星期、秒、指针和混合面，；时钟局部旋转已移除，整个画面服从系统方向。

## 蓝牙：开机有限尝试与手动操作优先

- 开机和深睡重启默认开启蓝牙，由服务线程尝试最近配对的有效设备，复用手动“连接”的流程。电脑/手机仍需响应指定目标邀请。用户取消、断开或关闭优先，手动/省电关闭后不会被轮询重新打开。
- 连接新外接键盘：开启蓝牙后从附近列表选择；仍需近期扫描、可连接广告、加密及HID服务发现就绪。
- 已配对外接键盘：“查找并连接”执行一次10秒扫描，按身份地址（含SDK/IRK解析）确认目标存在后连接。找不到即返回失败，必须再次手动操作，没有30秒周期重试。
- 已配对电脑/手机：“请求连接”发送最长60秒的普通可连接广播邀请，CONNECT只接受选中的已解析身份及角色，不使用定向广播。对方是Central，最终连接由对方发起；界面明确显示等待对方，不能保证所有主机系统会响应。无响应时需在对方蓝牙设置中点连接。
- “允许发现”是独立的60秒用户操作；再次点击可停止，超时后停止全部可连接广播，不再转入无限可连接广播。
- 已配对详情和蓝牙主页可以取消正在进行的连接。成功建立后的主动/对方断开，以及真正安全失败、取消、超时、host reset均不恢复后台连接许可。
- 连接许可来自本次开机有限尝试或手动会话；未完成的Peripheral短连接仅在远端0x13收尾、无真正SMP错误且未取消时，可在原60秒剩余时间恢复同一被动邀请，不延长、不换目标。取消/关开关后到达的旧连接拒绝；reset使旧扫描generation失效。
- 忘记设备同样撤销其待连接会话，保留单设备/全部配对删除确认。旧配对与Wi-Fi密码没有被清空。
- 保留单连接上限、键盘输入/本机HID输出两角色、系统配对、错误与真实Connected区分、受检PSRAM主机栈和超时。输出媒体仍为HID遥控，不增加A2DP或外接鼠标。

## 开机默认值与电源边界

每次启动/深睡重启将蓝牙和Wi-Fi运行时偏好置true、运动感应置false，不从旧NVS开关恢复；密码、网络历史、蓝牙密钥、时钟和其他偏好保留。

Wi-Fi驱动、STA网络接口和扫描缓冲在启用时初始化，开机自动请求最近成功网络；后续用户也可手动选择网络。保留目标存在性探测、有限重试、START/STOP/ScanDone隔离、DHCP成功才保存密码。

统一方向服务在系统运动许可开启、亮屏且前台应用未锁方向时发布采样需求；时钟不再直接使用IMU。FC和迷宫仅在系统开关开启时获取游戏采样需求，整个App前台锁定屏幕方向；游戏暂停/退出撤销临时需求。GUI读取缓存，初始化和I2C控制在服务线程。[方向](screen_orientation.md) · [FC控制](fc_touch_controls.md)。

CPU热重启可能保留外置IMU寄存器，启动服务只执行一次只关不启的操作：CTRL7关采样、CTRL1进入idle，随后移除临时I2C设备句柄。它不创建App，也不完整初始化采样器；真正初始化延迟到用户使用。硬件无响应时日志告警，不能伪称成功关闭。

PWR通常亮灭屏；文本阅读/加载及相册图片查看页（含图片加载/失败）单击返回文件列表，离开内容页恢复，屏幕已灭时优先唤醒。设置/快捷面板共用深睡收尾，RTC计时、GPIO5快速双击唤醒及长按关机规则保留。普通灭屏不算退出App，不主动拆掉已建立无线连接；深睡重启后Wi-Fi和蓝牙默认开启并尝试历史目标，系统运动默认关闭。

计时器前台常亮并接管KEY/PWR，退出恢复系统偏好与按键；BOOT双击退出。萌芽物语BOOT单击当前页返回，普通熄屏暂停动画，唤醒后记忆演示重新倒计时；保存由独立短时worker收尾，不因保存回执重建页面。详见[计时器](timer.md)与[萌芽物语](garden.md)。

## 生命周期与资源

`WindowManager`从覆盖栈改为单个`unique_ptr<App>`。注册表只存名称、图标、工厂。打开请求延迟至GUI泵执行，先销毁旧应用，再创建新应用，不预建或隐藏缓存App。

销毁顺序：关闭快捷面板、销毁共享输入器控件/弹层→清外接键盘焦点/排队按键/连按→onHide→onDestroy→删除LVGL根→释放App对象。支持内部返回的文本/设置页面仍按原规则导航；真正退出才销毁。

- 键鼠退出停止连击，释放拖拽及候选字符；各App定时器停止/删除、事件订阅注销。
- FC暂停并等待worker结束SD存档/媒体I/O，释放ROM、输入和临时重力需求；三个手动槽及独立自动档保留在nes目录，a/b不是清理对象。读档后先回暂停菜单，手动继续。
- 时钟停止刷新；重力迷宫撤销游戏采样需求；小恐龙保存高分并删除timer；万年历与黄历停止更新/动画；手电停止SOS并恢复亮度。旧触控展示已移除。
- 截图是系统短时任务，退出App不强杀已开始的写盘；深睡/重启等待保存收尾。主题切换先结束App再保存并重启。
- 设置退出取消用户发起的扫描，不误取消手动连接拥有的目标探测，也不自动断开系统已建立连接。
- 文本/相册继续取消共享存储任务和释放UI/图片。文本读取缩为2KiB分块，每块之间检查取消；目录取消后不再排序。
- 正在执行的底层I/O需安全返回后回收任务资源，不强杀持有SD/驱动锁的任务，因此不承诺退出瞬间所有内存同步归零。

系统服务、Home、时钟计时和用户连接不是后台App实例。BLE栈首次启用后保留系统GATT/host资源，避免异步回调未结束时析构造成崩溃；关闭无线停活动，不执行危险的运行时彻底deinit。Wi-Fi底层同样首次使用后保持安全系统生命周期。

自动策略另按前台提示和忙状态工作，常亮低负载可按用户选择关闭闲置无线，熄屏到期且设置允许时先请求深睡，收尾再等待录放音/游戏/热点/同步/SD结束；后台会话不推迟暗屏期限。插电两项开关默认关闭，未知供电在启动时暂按保护处理，连续30秒无外电信号后按电池运行执行省电；仍可手动启用供电保护。见[电源管理](power_management.md)。

## USB画面投放

设置→显示与声音手动开启，电脑接收器显示首帧后只关闭背光。设备逻辑亮屏、触摸/按键、LCD刷新、性能锁及游戏保持运行；离开设置不会结束投放，这是系统会话，应用仍遵循退出销毁规则。

普通关屏、深睡、关闭投放、接收器断开或超时会停止会话，同核清理USB驱动并清零释放帧缓冲；深睡等待清理完成。结束时仅在逻辑亮屏时恢复背光。文本/图片页PWR返回列表仍保留，不误当普通灭屏。无音频或电脑反向输入，见[使用说明](usb_display.md)。用户确认电脑投放可用，拓展坞直连显示器方案已放弃。

## 本轮清理与验证边界

当前20个App，设置最后；只移除独立深睡App，保留设置和快捷面板的深睡操作。语音助手、自有模型/训练入口及无使用者的BSP触控观察包装已移除，基础触控不变。

TextInput仅保留系统触摸钩子和少量类型/字符选择状态；每次显示创建控件，隐藏/导航时关闭下拉并删除整个控件树。阅读进度任务创建失败也回收队列容量。下拉面板同样按需创建、关闭销毁，无独立常驻轮询任务。
