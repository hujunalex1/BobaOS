# USB 画面投放到电脑

入口：设备「设置 → 显示与声音 → USB 画面投放」。此功能已经编译、烧录，用户于2026-09-23反馈“电脑投放没有问题”。当前只交付电脑接收方式；固件与启动校验见[当前状态](../current-state.md)。

## 使用

1. 用支持数据传输的 USB 线连接雨墨设备和本机电脑；USB连接模式需为“开发与烧录”，若处于[SD读卡器](usb_storage.md)模式先确认切回。
2. 在设备上手动开启「USB 画面投放」。未收到电脑首帧确认前，设备屏幕正常显示。
3. 双击 [pc-display/Start-Display.cmd](../../desktop/pc-display/Start-Display.cmd)。选择雨墨设备对应串口，再点击「连接」。端口以当前电脑实际枚举为准。
4. 电脑完整显示第一帧后，设备关闭背光。设备上的触控、实体按键及已连接的蓝牙键盘继续按原应用规则工作。
5. 可点击「全屏」或按F11切换全屏，Esc退出电脑全屏。画面按整数倍等比例放大、黑底居中；源画面仍为240×240。
6. 电脑点击「断开」、关闭接收窗口，或在设备设置中关闭投放，结束本次会话。连接丢失也会超时退出；逻辑屏幕仍亮时恢复设备背光。再次使用需在设备上手动开启并重新连接。

程序只在点击连接后打开串口，不自动连接或随电脑启动。Windows启动器使用PATH中的Python，需要Tkinter和pyserial，安装步骤见 `docs/desktop/pc-display.md`。无需启动密码本服务。

## 交互和使用范围

- 投放属于系统显示功能，退出设置、切换应用后继续有效。它不保留已退出的App实例。
- 关闭的只是本机背光，系统仍认为屏幕处于亮屏状态，LCD刷新也继续进行。FC不会仅因投放而暂停，触控和按键仍在设备上操作。
- PWR保留当前页面的原行为：文本阅读/加载页和相册图片页用于返回列表；其他页面普通关屏会结束投放。若通过PWR关屏结束，设备保持正常灭屏，下一次PWR再唤醒。
- 自动息屏、深度睡眠也结束投放；深睡等待USB任务清理。开机及深睡唤醒均默认关闭投放。
- 声音仍由设备播放；电脑接收窗口不提供音频传输、鼠标/键盘反向控制或录像。
- 投放显示实际屏幕内容，密码本主动显示的明文也会出现在电脑窗口。断开后窗口清空，设备投放缓冲在释放前清零。
- 烧录、串口监视器与接收窗口不能同时占用同一串口。烧录前先断开并关闭接收窗口。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 串口列表没有设备 | 检查数据线及连接，点击刷新，按当前设备选择串口。 |
| 提示串口无法打开 | 关闭占用该端口的监视器、烧录程序或另一接收窗口后重试。 |
| 设备仍亮、电脑等待画面 | 确认设备开关已开启且电脑点击了连接；首帧未成功呈现不会关闭背光。 |
| 提示连接中断 | 结束旧连接，重新开启设备投放并连接。设备不自动循环重连。 |
| 提示内存不足 | 退出当前占用较多内存的应用后重试。 |
| 静止时显示帧率很低 | 静止画面不重复发送，接收帧数不是游戏的模拟帧率。 |

## 实现与验证边界

`DisplayCast`在LVGL的 `LV_EVENT_FLUSH_START` 捕获LCD交换字节前的RGB565区域，合成完整帧，覆盖普通界面和FC画面。协议带会话、序号和头部/负载CRC，使用RGB565原始数据或PackBits式无损压缩；电脑完成显示后ACK，设备只发送最新画面，不积压历史帧。

发送间隔下限50ms，即调度上限20帧/秒，实际取决于画面变化、USB和电脑处理时间，不代表已测得20fps。只有手动开启才创建core0任务和三个115,200字节PSRAM帧缓冲（合计345,600字节，另有任务栈、USB缓冲等开销）；关闭后成对卸载USB驱动并释放。USB辅助日志在投放期间暂停写入，主UART诊断保留，结束后恢复USB日志。开发模式的USB身份与烧录方式保持现状；SD读卡器另使用MSC接口，与投放互斥。

已有10项生产C编码/模拟USB接收测试及不打开串口的GUI冒烟测试通过，见开发收据（历史开发记录未随源码分发）；四区烧录及启动检查见烧录收据（历史开发记录未随源码分发）。用户反馈确认电脑投放可用；没有独立记录实际吞吐、端到端延迟、长时间游戏帧率或所有断线场景的实测结果。

## 已放弃的普通显示器直连方案

2026-09-23用户确认拓展坞为绿联6合1CM818-45363，随后明确放弃普通显示器直连方案。保留已实现的电脑USB投放；没有开发拓展坞直连、独立接收盒或新增硬件方案，也不把这些作为待办自动继续。

此前核对的结论：此类Type-C转HDMI拓展坞需要上游DP视频信号，独立PD供电不能将雨墨的自定义USB画面数据转换成视频；当前板卡没有原生DP/HDMI输出。型号依据为[绿联45363官方说明](https://www.lulian.cn/download/241.html)，硬件依据为[ESP32-S3资料](https://www.espressif.com/sites/default/files/documentation/esp32-s3_datasheet_en.pdf)。这是接口能力边界，不是已完成拓展坞实机兼容测试。
