# FC游戏手动存档、自动存档与读取

当前提供1～3号手动存档位，列表顶部另有一个自动存档位，只能读取，不能手动覆盖。文件保存在SD卡 `/nes/` 中，与 `.nes` 游戏同目录。旧4、5号位不再显示或读取，也不会被当作自动槽。游戏基本操作见[FC控制说明](fc_touch_controls.md)。

## 自动保存

游戏实际运行满一分钟后首次自动存档，之后每累计一分钟运行时间尝试一次；进入列表、加载或暂停菜单不会计时，更不会一开游戏就覆盖旧自动档。读档后重新等待一分钟。失败不会每帧重试或连续补写。

在帧边界复制独立状态快照后，游戏继续运行，短时写盘任务负责校验、分段写入、同步和回读；不再让整个SD写入阻塞游戏线程。快照复制仍有有限成本，不能保证任何SD卡都完全无帧时抖动。退出游戏或打开存档页先等已开始的自动写入收尾，避免退出释放快照时丢档；休眠或SD不可用时安全取消并保留此前有效代次。自动存档不是退出时强制新建存档，最后不足一分钟的进度需要手动保存。

## 保存

1. 游戏中点击屏幕下方中间隐形区域，或按蓝牙键盘Space，打开暂停菜单。
2. 点击「存档/读取」，等待列表加载。顶部是自动槽，下方为三个手动槽。
3. 选择一个位置，再点击底部「存档」。空白位置可直接保存；已有记录（包括损坏记录）会弹出覆盖确认，取消则保持原状。
4. 等待出现「存档成功」，再返回暂停菜单，点击「继续游戏」。操作期间不要拔卡。

每行显示编号、保存的年月日时分秒以及游戏时长。保存时间取设备时钟，请先确认时间正确；没有有效时间时显示占位日期。游戏时长按实际已模拟的帧数除以50/60Hz计算，不包含暂停时间，也不等同于受卡顿影响的现实经过时间。

## 读取

1. 先打开对应游戏，再进入「存档/读取」。不会从游戏列表自动加载存档。
2. 选中有效记录后「读档」才可点击；空白或校验无效的记录不能读取。
3. 读档成功返回游戏暂停菜单，显示「读档成功，点击继续游戏」。点击「继续游戏」后才继续运行，并恢复存档中的进度及游戏时长。

读写期间禁用相关按钮，防止重复操作。存档/SD发生变化或读写失败会提示原因；需返回或显式刷新后重新选择。无效、不兼容的存档不覆盖当前运行进度。

## 文件和兼容性

手动文件格式：`nes/ym-<完整ROM文件SHA256>-<1到3>-<a或b>.sav`；自动文件格式：`nes/ym-<完整ROM文件SHA256>-auto-<a或b>.sav`。由App生成，不需要手工创建。ROM只改文件名仍可识别原存档；修改ROM内容或换成另一版本会使用另一组存档。

每个逻辑位置最多有a/b两份交替写入的代次文件：保存写入另一份，完成同步、关闭和回读校验后再作为最新有效记录。另一份是防中断的内部存储机制，不是额外的用户存档位。单份状态负载上限256KiB，另有96字节文件头，实际占用取决于游戏状态和SD卡簇大小。不要把配套的a/b文件误当成无用临时文件清理。

状态包含CPU、PPU、APU、Mapper寄存器、工作RAM/CHR-RAM、输入状态及画面；不保存进程指针。读入前检查ROM身份、格式/布局、制式、音频配置、CRC及页映射。存档是雨墨当前核心的专用格式，不与其他模拟器通用；后续改变核心布局或音频配置的固件也可能拒绝旧档，不承诺跨版本兼容。

手动存档会保存当时的RAM状态，但尚未实现独立的电池SRAM自动持久化。异常断电、坏卡或带电拔卡仍可能造成文件系统损坏；退出App完成I/O收尾后，使用[安全弹出SD卡](sd_media_fc_20260918.md)再拔卡。

## 实现与验证

界面在 `main/apps/fc_player_saves.cpp`，请求和SD会话在 `main/core/fc_saves.cpp`，双代次文件在 `fc_save_store.c`，核心序列化在 `components/nofrendo/nes/checkpoint.c`。手动保存/恢复在暂停后的帧边界由原FC任务执行；自动快照的写盘由按次创建的任务执行，GUI不访问文件系统。退出等待任务结束并释放文件、SD会话及临时缓冲。

初版开发收据（历史开发记录未随源码分发）属于旧五槽手动版本，不能作为本次自动写盘验收。当前策略可核对 `tools/fc_autosave_model_test.cpp` 及最新构建检查（历史开发记录未随源码分发）；本次文档整理没有重跑FC实机测试。用户ROM、真实SD掉电和性能仍需实测，当前产物见[项目说明](overview.md)。
