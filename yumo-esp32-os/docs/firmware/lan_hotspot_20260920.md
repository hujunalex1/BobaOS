# 局域网：自动共享当前 Wi-Fi

Yumo 中文为“雨墨”；默认热点名仍为 `Yumo-LAN`，不改变已保存的热点名称。

更新日期：2026-10-31。自动共享及热点浏览器功能均已烧录。交付来源与验证边界见[当前状态](../current-state.md)。

## 使用方式

1. 打开“局域网”，按需编辑热点名称和密码，再打开热点开关。进入应用及开机均不会自动开启热点。
2. 设备已连接 Wi-Fi 且取得有效上游地址、网关与 DNS 时，自动显示“共享当前 Wi-Fi”，子节点可经设备访问上游网络，无需选择共享模式。
3. 设备未连接 Wi-Fi 时，同一热点提供“本地局域网”。手机提示无互联网时，选择保持连接，仍可用各设备自己的软件进行本地通信。
4. Wi-Fi 已开启但尚未连上时，保留原有连接流程；取得上游网络后自动启用共享。Wi-Fi 原本关闭时不会为了热点擅自开启 STA 或修改已保存凭据。
5. 修改热点名称、密码前先关闭热点。名称、密码沿用原设置并由系统保存；热点开关不持久化。最多接入 4 台子设备。
6. 关闭热点或退出应用会释放热点资源；此前借用的普通 Wi-Fi 连接保留。普通 PWR 熄屏不会立即关闭热点，达到既有深睡条件后仍会结束热点再休眠。深睡唤醒不自动开启热点。

“自动”指上游可用性判断与共享切换，热点开关仍由用户控制，没有两套手动模式。

## 状态与地址

| 页面状态 | 含义 |
| --- | --- |
| 本地局域网 | 热点可组网，当前没有可用的上游 Wi-Fi |
| 共享当前 Wi-Fi | 已配置 IPv4 转发；上游本身是否能访问互联网取决于所连网络 |
| 共享重试中 | 已发现上游，但 DNS、地址或转发配置暂未完成；保留本地热点并重试 |

热点默认名称仍是 `Yumo-LAN`，名称允许 1～32 字节且不能全为空格；密码为 8～63 个可打印 ASCII 字符。热点采用 2.4GHz、20MHz、WPA2-PSK；独立 AP 初始信道为 6，共享时跟随上游 STA 信道。

默认网关为 `192.168.4.1/24`。若与上游网段重叠，自动依次尝试 `192.168.77.1/24`、`172.31.77.1/24`、`10.77.0.1/24`；以页面实际地址为准。客户端通过 DHCP 获取地址，上游 DNS 通过 DHCP 下发。网段或 DNS 改变时会让子设备重新连接、刷新租约，可能短暂中断已有会话。

上游掉线时关闭互联网转发，保留本地热点和 DHCP；上游恢复后自动重建共享。Wi-Fi 仍使用受控重试；热点借用期间普通非鉴权失败可继续慢速尝试，密码被拒绝不会无限重试。

## 功能边界

采用 APSTA 与 IPv4 NAPT，子节点处于独立子网，不是把上游 Wi-Fi 原样桥接。未新增IPv6共享或端口映射入口。热点内新增独立HTTP文件/密码网页，旧全局文件服务仍保持移除。上游设备发现与第三方互传软件仍受各自协议、防火墙和网络隔离设置影响。

客户端列表显示 MAC 尾号标识、完整 MAC、IP、信号强度和无线流量估算。“设备 XXXX”不是识别出的品牌或设备名称；静态地址或租约未取得时，IP 可暂显示 `-- (DHCP)`。

## 界面与速率

240×240 单页保留原热点开关、名称/密码输入、设备列表；编辑框使用系统键盘。名称/密码行 36px、开关行 40px，键盘两行各 54px。应用退出释放界面和 500ms 刷新定时器，热点启用时启动HTTP服务，文件任务遵循现有SD占用和深睡收尾。

统计区域显示无线流量估算，使用十进制 B/s、KB/s、MB/s；不是协商速率或文件有效吞吐。上传统计发往本 AP 的数据帧长度并去除相邻重传，下载依据 SDK AP 发送成功回调；约每秒按实际间隔采样。只读取帧头和长度，不保存数据内容。内部转发、聚合、重传以及统计回调覆盖范围均可能造成偏差；热点与 BLE 并行的吞吐、功耗和统计精度没有量化实测。

## 维护入口

- `main/apps/lan.*`：界面、输入校验与应用会话。
- `main/core/lan_hotspot.*`：系统 worker 拥有的热点状态机、DHCP/DNS/NAPT 与统计回调。
- `main/core/lan_routing.hpp`：IPv4 网段重叠检查与网关选择。
- `main/core/lan_hotspot_model.hpp`：默认值、4 台限制、输入校验与速率模型。
- `main/core/connectivity.*`：借用现有 STA、报告上游地址并保留其连接；借用期间阻止整套 Wi-Fi 驱动重启或释放。
- `main/core/settings_store.*`、`power_mgr.cpp`：保存热点配置与深睡收尾。

共享热点结束时先关转发及统计，再从 APSTA 回到 STA，仅释放 AP 接口。独立 AP 则沿用原驱动停止、事件收尾和销毁流程。若停止失败，保留错误与重试状态，不销毁活跃接口；取消请求不依赖可能满的命令队列。

配置需要 `CONFIG_LWIP_IP_FORWARD=y`、`CONFIG_LWIP_IPV4_NAPT=y`；SDK 默认连带启用 NAPT_PORTMAP，但本应用没有建立端口映射。AP_STOP/AP_START 以最新事件更新状态，覆盖已运行 STA 上增设 AP 时先停后启的事件序列。

## 验证范围

开发工程已完成 747 项源码检查（原有 45 项排除未扩大）、41 个交叉编译模型和 3 项防护检查。Wi-Fi 生命周期回放覆盖 19,518 项检查、307 个场景，LAN 生产状态机回放完成 807 项检查。

实机短测中，一台子设备通过热点取得 DHCP 地址、完成 DNS 解析与 HTTPS 请求（HTTP 200）；观察到本地热点自动转为共享，以及关闭热点后 STA 保留。诊断代码已从最终镜像移除，最终固件通过四区烧录校验和启动检查。尚未量化真实断网重连、四客户端压力、长期稳定性与吞吐；宿主故障注入不能替代这些实测。

## 热点浏览器：Wi-Fi硬盘与密码

热点打开后，手机连接该热点并访问设备页面显示的HTTP地址（通常`http://192.168.4.1`，网段冲突时会变化）。访问限制同时检查实际AP地址、客户端子网和请求来源；已修正IPv4映射IPv6套接字导致的错误拒绝。用户已反馈地址可以打开。

Wi-Fi硬盘管理SD目录，支持分页浏览、创建文件夹、重命名、删除、上传和下载；目录及不同文件类型使用内置SVG，不依赖外部字体图标。每次上传上限256MiB，流式写入临时文件，收到完整长度并同步后提交，同名文件不静默覆盖。SD读卡器独占、存储忙或卸载时按实际状态拒绝冲突操作。

密码入口使用与设备密码本相同的九点图形密码，至少连接4个不同点；跨越尚未经过的中点时自动补点。首次图形密码需先在设备上设置；网页复用现有校验与错误等待机制。解锁后先显示四个分类按钮：工作按单位/系统、应用按名称/平台、网页按账号再用途、其他直接展示码值并隐藏账号；支持明文复制。只读查询，不修改密码库。最多4个浏览器会话、会话5分钟；锁定、离开/隐藏页面或切回文件页清理明文，迟到响应不能恢复已锁页面。

两行原固定说明已移除，空间用于访问地址和状态；实际输入错误仍显示。普通关屏遵循原电源策略，达到深睡条件或退出应用时先排空HTTP/SD工作再关闭热点。HTTP没有传输加密，应在本人控制的设备热点中使用；文件页不额外要求密码本图形密码。

维护入口增加`core/lan_web.*`、`core/lan_web_protocol.hpp`；网页随固件内嵌，不需要另启PC服务。源码、浏览器模拟和生产处理函数回放已通过；手机打开页面反馈不等于全部真实SD上传下载、并发或掉电路径已实测。
