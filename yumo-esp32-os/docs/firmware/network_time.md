# 网络校时与休眠时钟自学习

更新日期：2026-10-15；对应 2026-10-14 已成功烧录版本。来源和验证范围见[当前状态](../current-state.md)。软件按每次可信联网校时得到的偏移更新观察窗口，满足条件后学习离线深睡补偿系数；没有固定的每日误差保证。

## 使用与自动校时

Wi-Fi 连接可访问互联网的网络后，可在“设置 → 日期与时间”点击“使用网络校时”。页面显示进度、服务器尝试序号和真实结果，成功后一起刷新年月日时分秒。Wi-Fi 默认开启并尝试最近成功网络，蓝牙不是校时前提；Wi-Fi 已连接不代表 DNS、NTP 或外网可用。

时间按中国时区 UTC+8 显示。手动保存日期与时间仍可用：系统 worker 先停止 SNTP，再应用手动值，防止旧网络响应覆盖；同时丢弃本轮学习观察窗口，保留已学到的有效系数。重复点击不会创建额外任务或延长超时，下拉框不会每次刷新都重置。

依次尝试 `ntp.aliyun.com`、`cn.pool.ntp.org`、`pool.ntp.org`，每台最多约 20 秒。连接恢复后可发起校时；保持连接时，成功间隔一小时刷新，失败间隔 15 分钟重试。自动请求只在逻辑亮屏时开始，不为校时唤醒暗屏设备；用户可随时手动重试。

校时是有界系统任务，亮屏省电阶段保留必要无线资源；普通手动熄屏不会直接取消它。暗屏达到明确设置的深睡期限仍按系统收尾，断网或深睡停止 SNTP 并释放资源；退出设置页后可继续到完成或超时，不保留 App/LVGL 对象。

## 深睡校准与唤醒补偿

RTC 慢时钟仍使用内部 RC_FAST/256（ESP32-S3 内部约 17.5MHz 振荡器分频），启动配置为：

```text
CONFIG_RTC_CLK_SRC_INT_8MD256=y
CONFIG_RTC_CLK_CAL_CYCLES=3000
```

排查发现，固定 SDK 的深睡最终路径会再用 10 周期校准，覆盖此前启动校准结果。当前通过项目链接包装 `--wrap=rtc_clk_cal` 在实际深睡入口接管这次测量：连续测量 3 次、每次 3000 周期、取中位数，并将结果交回 SDK。只在内部栈的深睡执行器即将入睡时启用，不直接修改 SDK 或其他校准调用。

三次测量均在合理范围内、离散度不超过 2000ppm 时，本轮才可用于补偿和学习。测量值范围为每 RTC tick 8～30 微秒（Q19 格式）；这些是异常筛选条件，2000ppm 不是走时精度。无效测量按实现回退，丢弃不可信观察窗口，避免把坏数据写入模型。

RTC 保留区记录深睡起始 ticks、校准值、可信标记、观察窗口及校验和。快速双击 PWR 被接受后，`Settings::load()` 之后、首次 UI 之前执行 `ClockDiscipline::boot()`，对本次可信深睡应用一次补偿。被 wake stub 拒绝的单击继续深睡，不清掉累计睡眠，也不重复补偿。

蓝牙仍使用主晶振。该方案不增加定时唤醒、不禁用深睡、不改变插电/连接保护和退出收尾优先级。此前切换 RC_FAST/256 约增加 5μA 是 SDK 芯片级估计，持续深睡 24 小时约 0.12mAh；不是本次软件改造的整机电流实测。

## 每次联网如何学习

`--wrap=sntp_set_system_time` 在 SDK 真正修改系统时间之前捕获本地时间，再调用原 SDK，保留校时完成信号和回调。worker 在 `esp_netif_sntp_deinit()` 的同步边界之后消费结果；网络回调不写 NVS、不操作界面。日志记录网络时间减校正前本地时间的偏移，首次可信校时只建立基准。

后续两次可信校时之间，满足以下条件才更新系数：

- 累计原始深睡至少 1 小时，且经补偿的深睡时长占校时间隔至少一半。
- 校时间隔为正且不超过 30 天，RTC 记录、校准和系统时间有效，累计时长合理。
- 推算所需补偿频偏在 ±2% 范围内；异常、多次冲突捕获和不可信校时不参与学习。

每次可信校时都会开始新的观察窗口；太短或以清醒时间为主的窗口不更新系数。首个有效样本直接得到估计值，此后累计深睡至少 8 小时的样本权重为 1/4，1～8 小时为 1/8。估计包含此前已经应用的补偿，防止校准后下一轮系数回零、往复振荡。

模型保存 `ratePpb` 与有效样本数。有效更新由 Settings 按版本化、带校验的 `rtc_drift_v1` NVS blob 持久化，沿用后台合并提交和失败重试。冷启动、普通重启、手动改时及异常 RTC/校准使当前观察基准失效；已持久化的有效系数保留。时钟仍按分钟保存检查点，网络/手动校时后顺延下一次保存，关机/深睡保留强制保存。

## 精度与硬件边界

偏移记录使用微秒，频偏参数最小步长为 1ppb；这是计算与存储分辨率，不是实机微秒级精度。实际误差还受内部 RC 温度漂移、睡眠环境、NTP 采样时刻与网络延迟、有效学习样本数量影响。更长且可信的睡眠窗口通常更有利于估计，不能据此承诺固定的 ±几秒/天。

用户曾反馈旧版本休眠 16 小时快 4 分钟，约 +4167ppm；这是本次优化前的观测，不是新版本误差，也没有硬编码成所有设备的补偿值。2026-10-14 烧录后捕获到首次 NTP：`samples=0`、`result=0`，证明基线流程已运行，尚不能证明已完成有效学习或长期误差验收。首次校时偏移不能全部归因于休眠漂移。

官方标准板原理图未见独立 RTC 芯片或 32.768kHz 晶体，详见[硬件核查](hardware.md)。完全断电后没有独立供电 RTC 可恢复断电时长，需要重新校时；不要把软件补偿当作独立 RTC。

## 日志判读与实测方法

`clock: NTP` 行包含 `offset`（校正前偏移，微秒）、`sleep`（累计原始深睡，毫秒）、`prior_correction`（已应用补偿）、`rate`（ppb）、`samples` 与 `result`。负 rate 表示减慢走快的时钟，正 rate 表示补足走慢。`clock: wake` 行记录本轮原始时长、实际补偿、校准和离散度。

| result | 含义 |
| --- | --- |
| 0 Baseline | 首次建立可信基准，未学习 |
| 1 Short | 累计深睡不足 1 小时 |
| 2 Awake | 深睡占比不足，不把清醒误差归入深睡 |
| 3 Invalid | 时间、记录、测量或频偏不可信，本轮不学习 |
| 4 Learned | 已接受一个有效样本并更新系数 |

建议按下列顺序验证：

1. 联网成功校时，建立可信基准，记录样本数和系数。
2. 离线深睡至少 1 小时，建议 8～16 小时；记录实际时间和环境。
3. 唤醒后在自动 NTP 修改时间前比对参考时钟，或读取 NTP 捕获的校正前 offset。启动会尝试自动联网，应避免自动校时掩盖原始偏差。
4. 联网确认 `result=4` 且样本数增加；这是学习周期。
5. 再进行一轮同等条件长睡，测量补偿后的残余偏差，并在不同温度下重复。

残余误差折算：`每天误差 = 本轮残余秒数 × 86400 ÷ 实际间隔秒数`。例如 16 小时剩余 2 秒相当于 3 秒/天，仅为换算示例。需同时记录有符号误差、时长、样本数和温度，不能把单轮偶然吻合当作精度上限。
